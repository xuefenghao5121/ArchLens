# RTL 生成判断支持

## 正确用法（判例检索，非清单装载）

**任务开始时**：`python3 platform/tools/caselaw.py search "<你的情境描述>"`
**每次失败时**：`python3 platform/tools/caselaw.py search "<报错信息/失败签名>"`

命中判例按"做法"执行；无命中正常推进；工作结束后 `caselaw add` 沉淀新判例。
依据：RSI 配对 A/B 实测规则清单下发零增益（详见判例 CL-015）——经验的判断成分
在情境匹配检索里，不在预装载的清单里。

## R1-R10 参考材料（人的速查，非下发清单）

来源：CVDP 50 题盲测（非代理 20 + agentic 30）失败模式挖掘。
目标：首发通过率 ↑、不可解题的评估预算 ↓。

## R1 仿真器替换保真度
替换仿真器时逐项核对：警告是否致命（icarus→verilator 需 `-Wno-fatal`）、
参数传递格式、timescale 默认值、SV 支持子集。

## R2 RTL 写法检查项
- 多个 always_comb 禁共享模块级循环变量（MULTIDRIVEN），用块内 `for (int i...)`
- 优先级链：组合块"最后赋值获胜"——要最高位优先就用升序循环
- 单 bit 激励对 ≠ 功能对；自测必须含多 bit 组合激励

## R3 失败分诊
ERROR（无测试输出）→ 查 build（缺文件/参数/编译顺序）；FAIL → 读断言消息定位。

## R4 黄金模型先行
位打包/定点算术/参数化遍历类题，先写 Python 黄金模型对语义全参数自测，再写 SV。

## R5 反馈通道自检
每条 FAIL 必须携带可判读反馈或显式 `NO_ASSERTION_FOUND`。评估器侧保证；
解题侧遇到反馈贫乏按 R9 止损。

## R6 编译自包含（agentic）
编译源 = DEPLOY 目标文件；repo 既有模块不一定参与编译。
解法一律自带内联/改名副本，防 MODMISSING/MODDUP。（rc5 教训→async_fifo 受益首发过）

## R7 断言数值解释
runner 断言里的 "0x" 前缀可能是十进制数（`0x37053`=37053）；expected/got
字段先对齐数值再推理语义。（rc5 破题关键）

## R8 握手语义预扫（首发杀手 #1）
done/valid/busy/watchdog 类信号的语义是首发失败最大单一来源。提交前在自建 TB 里
把二义语义各测一遍：脉冲 vs 电平保持、门控 vs 自由运行、完成拍 vs 完成后一拍。
能两种解释都兼容就写兼容版。（AES_0005/nmea/thermostat 三题同因）

## R9 止损协议（预算再分配）
不可解题的特征签名，命中即早停，省下的预算给可解题：
- **bench 缺陷签名**：harness 施加激励前崩溃 / context 缺失但 prompt 引用 → 1 eval 即停，如实记缺陷
- **反馈贫乏签名**：`NO_ASSERTION_FOUND` 或空聚合消息连续出现 → 3 eval 即停
- **架构性反推签名**：文档与断言期望出现架构级分歧（不是字段级）→ 最多 3 probe
  后停（ethernet_mii 教训：死在最后一个寄存器地址，6 eval 不值）

## R10 上游检索-验证法
规格不足时先检索公开上游实现（开源库/官方规范）按精确语义实现；**但 packet 参考
实现可能偏离上游**（custom_fifo 与 ibex 相反）——上游语义只作首发假设，
以评估反馈为准修正，必要时用输出值演变反推私有语义。

## 止损省下的预算用途
按 R8 预扫、R4 黄金模型全参数自测——把预算从"不可解题的盲目试错"
转移到"可解题的提交前验证"。
