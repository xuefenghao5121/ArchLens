# 调度规程：一轮迭代怎么推进

## 为什么存在

平台的信任建立在三件事上：显式契约、独立验证、结论边界。这三件事都要求「谁在什么时候看到了什么」是可查的。如果编排逻辑留在某个 agent 的上下文里，它为什么跳过一层、为什么觉得「看起来没问题」就放行，人事后都查不到。

所以顺序不靠 agent 记：模板定这一轮有哪些框、什么顺序；核对规则定一个框何时算完成；派发按本规程。调度 agent 只做四类动作——定位、造包、派发、收工——再加上把要人决定的事端出来。它不做任何一层的层内工作，也不对微架构问题下判断。

## 五个动作

1. **定位**：`wf next`。看当前前沿层、该层的 agent、待做的包；同时看任务提示里有没有待批的章程或开迭代决策。有待人决定就先停下。
2. **造包**：`wf brief <包> --out --by <署名>`。把开工简报落成这个包目录下的 `brief.md`，信封里记时间、署名、指纹和上游列表。这份简报就是派发时给的全部内容。
3. **派发**：用平台内部的运行时把这一层派给它的 agent（界面上的「派给 agent 开工」，或
   `python3 platform/tools/runtime.py run --pkg <包>`）。运行时读 `platform/agents/<层>/agent.md`，
   自己执行工具并跑 `wf gate`；不需要人工另开会话，也不跳外部界面。派发前确认上游都已核对通过。
4. **收工**：子代理说「做完了」不算。跑 `wf gate <包>`，用核对结果说话；再用 `wf run-log --pkg <包> --agent <谁> [--model 名] [--duration 秒]` 记一条执行记录。没过就退回这一层继续改，不改判据、不隐藏失败。
5. **见人**：把 `wf card <包>` 端给人。这一层需要签字、或有待人决定的事项，就停在这里等人签；签完再往下。**决定发生在结果之后**：开工前不知道 agent 会产出什么，所以不要要求人提前提决定。高权重层只差签字时，平台按本层已产出的接口卡自动生成待签事项，人批准/驳回即可；手动补记已发生的选择，用界面的「补记决定」。

一轮的完成没有另外的定义：模板里每个框都到「已验证」，这一轮就完成了。之后是封板还是开下一轮，由人在 Mission Review 上定，两者都留署名决策。

## 硬规则

- **上游没验证完，不派下游**。核对规则本身也会拦（上游未验证时下游不能通过），但不要在知道的情况下还去派。
- **只给简报**。运行时只拿到开工简报；需要更多上游细节，走 `wf show <上游包> --for <本包> --by <署名>`：看的同时留痕，事后能回答「这一层额外读了什么」。
- **不替人签字**。层 agent 开工前声明 `WF_ACTOR=layer:<层>`；批准、驳回、署名覆盖、作废都只由人做，`wf` 会拒绝。调度 agent 自己也不签。
- **不改层包**。发现内容问题，交回该层 agent 改；发现判断问题，提请人决定。
- **不并行派工**。store 是追加式、没有并发锁；运行时同一时刻只允许一个作业，按模板顺序一层一层来。
- **不跳过核对**。子代理的完成声明、界面上的绿色、日志里没有报错，都不是完成。

## 什么时候停

- 有待人决定的事项（签字、驳回后的重做、待批的章程或开迭代）。
- 核对没过，而且原因不是这一层能自己修的（例如上游内容被改过，需要重新核对上游）。
- 上游被作废或核对后改过：先回去处理上游，不要往下推。
- 模板走完，或者人决定封板 / 终止这一轮。

## 与 NDF 做法的对应

| NDF | 这里 |

| Command 造 pack、等人审、派发 | 造开工简报、等人签字、派给层 agent |
