# Flow Layer Discipline——层输出与交接纪律

## 为什么存在

真实事故链：L2b/L6 的**交接建议**里各塞了一条"和软件方案比数字"，L3 照单全收立成判据，
L7 据此做出无效裁决——污染经由 handover 通道传播，两道防线（gate/人类批准）都没拦住。
本 skill 把四条通用纪律变成写任何层输出时的前置检查。

## 纪律一：每个数字带基架标签（F0-F3）

任何写进 envelope 的测量数字（周期、占比、拍数、吞吐）都必须标注它产自哪个时延模型：

- **F0** 仿真器默认参数（未校准）｜ **F1** 契约拍定参数 ｜ **F2** RTL 实测背书 ｜ **F3** 解析模型推导

写法：payload 里集中一段 `measurement_frames_note`（或 acceptance_criteria.measurement_frames），
逐数字标注。没有标签的数字 = 下游一定会误用的数字（历史证明）。

## 纪律二：交接只传特征量，不传对比锚

层间 handover/recommendation 的合法内容：
- 上游归因出的**特征量**（瓶颈份额、指令流构成、依赖链深、束缚约束位置、剂量关系）
- 本层工件的**机制参数**（接口、时序、资源三态）
- 下一步的**可证伪命题草案**与实验设计建议

非法内容（写出来就是污染下游）：
- "打赢/超过某方案的某数字"式的任何表述
- 把某个方案（软件优化、上一代、基线）的表现数字定位为"标尺/门槛/对照基准"
- 跨基架的绝对数字并置（除非显式标注"校准用途，非裁决依据"）

自检句式：把交接建议里的每个数字问一遍"这个数字是特征量还是别的方案的成绩单？"
后者就删掉或降级为带 F 标签的参照。

**载体是层接口卡**（2026-11-24 起，新建任务下的层包由 `wf gate` 强制）：信封的 `interface` 写明本层要回答
的问题、用了上游哪几条结论（`takes`）、交给下游的 1–5 条结论（`gives`，每条一句话，带真值
observed / deduced / assumed、基架 F0–F3、证据 `RES-…` / `ART-…`）、没解决的问题（`open`）与适用边界
（`limits`）。下游 agent 拿到的是这张卡（`wf brief`），不是上游全文——纪律二于是有了机械的落点。
核对同时强制：标「实测」的结论必须指向登记在册且通过的测试结果；上游没验证完，下游不能通过；
签字只对签过的那份内容有效，内容改过要重签；核对通过之后接口卡再改，「已验证」不再成立。
`wf guide` 给骨架，`wf card <pkg>` 看成卡。

## 纪律三：结论分级与局部循环优先

- 任何层出异常/预期未兑现时，**先回溯定位**（哪一层的哪个转换/假设错了），
  再决定：局部修订（supersede 新版本）还是终局判定。终局判定（rejected 类）只对
  "该候选该口径"有效，且必须写明适用边界——禁止把版本级结论升级成路线级死刑
- 结论三档语义分开写：实测（引 ART）/ 推断（写依据）/ 拍定（写来源）
- `model_causal_status` 与 `hardware_evidence_status` 分开；无校准证据禁 hardware_supported

## 纪律六：任务收敛（Mission Charter + Ship Gate）

真实事故（2026-11-17 用户指出）：三轮 L1→L8 全部合规闭环，但任务整体不收敛——每次 L8 的新
束缚定位天然成为下一轮入口，结构性保证无限迭代。真实芯片工程靠预算与 trade-off 签字收敛，
不靠"没有可优化项"。规则：

1. **无章程不立项**：任何新迭代/新优化点开工前，必须有任务章程。没有章程的"下一步"=
   不许开。章程是结构化的任务记录：**目标**（原话，锚定研究问题，之后每一层看到的都是这同一句）、
   **benchmark**、**流程模板**。任务长什么样、这一轮怎样算完成，只由流程模板决定（模板里每个框都已
   验证），不另写成功判据——判据写在方法论里由 AI 自己闭环，人无法检视。预算与停止规则不设成字段：
   要不要再来一轮、什么时候封板，是人在 Mission Review 上的决定，用理由留痕。
   流程：`wf bench-import` 导入 benchmark → `wf task-new` 立项（目标 + benchmark 缺一不立，写成
   任务级章程决策，署名或待批）→ 再迭代 `wf iter-new --reason` → 封板 `wf task-seal --as --reason`。
   （2026-11-24 之前的章程带成功判据 / 预算 / 权衡政策 / 停止规则四项，原文保留在任务记录里作为存档。）
2. **每次 L8 后必过 Mission Review**：判据达成→封板 SHIP；未达成且预算有余→一次有理由的
   再迭代（预算递减明示）；预算尽→按最优现状 SHIP + 已知限制清单（带 errata 出带）。
   禁止用"还有下一个瓶颈"作为继续的理由——瓶颈永远有，预算才会用完。
3. **SHIP = 两件交付物**：分析验证报告（L8 链综合 + **trade-off 选点签字表**：采纳什么/
   搁置什么/拒绝什么/挂账什么，各配依据）+ 仿真器交付件清单（平台+模型资产+复现+版本锚）。
   交付物入 store，封板决策留痕。
4. **Trade-off 是签字不是寻优**：剂量曲线（L7 产出）就是 trade-off 曲线；收敛的动作是在
   曲线上选点并签理由，不是找到最优点。搁置项特征量封存留档，重开需新章程。

## 纪律五：因果链表述（谁在做事，谁在验证）

任何结论/汇报里，角色不许说反：
- 正确链：**归因（L2）→ 微架构优化设计（L3/L4/L5）→ RTL 仿真验证（L6/L7）**
- 消除瓶颈的主体是**优化设计**；RTL 是**精确仿真验证手段**——其必要性 = gem5 纯软仿真的时延模型
  仿不出新设计单元的细节（时延/吞吐/结构行为），须以 RTL 建模保证验证可信
- 禁用句式："瓶颈在 RTL 仿真下被消除"（把验证手段说成了主体）；正确句式："优化设计经 RTL
  精确仿真验证，确认消除了归因的瓶颈"

## 纪律四：撤回与修订必须留痕

- 撤回结论：decide 记录 + `contradicted_by` 边；修订：新决策 + supersedes 链
- 数据与结论分开处置：裁决可废、数据保留（重新归类为 参照/同框有效/无效 并逐项标注）
- 禁止静默改 payload 里的结论性字段——改了就要有对应决策

## 交接前最后一眼（清单）

- [ ] 层接口卡写了？每条结论一句话，带真值和基架；标「实测」的指向登记在册且通过的测试？（新建任务必查）
- [ ] 本层所有数字都有 F 标签？
- [ ] handover 里没有"和某方案比"的锚？
- [ ] 异常项都定位到层并给了修订/终局的明确建议？
- [ ] 撤回/修订项都有决策留痕？
