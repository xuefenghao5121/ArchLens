# OKComputer · 微架构混合仿真研究工作台（React 前端）

对接 `platform/viz/server.py` 真实后端的 React 前端。设计说明见仓库根目录
`VISUAL-WORKFLOW-DESIGN.md`（§11 是流程编排与层接口卡这一版）。

## 技术栈

React 18 + TypeScript + Vite 5 + React Router（Hash）+ TanStack Query

## 运行

```bash
# 1. 先起后端（wf.py 的 viz server，端口 8899）。只想试用界面请加 WF_ROOT 指向一份副本
python3 platform/viz/server.py --port 8899

# 2. 起前端（Vite dev，端口 5173，/api 自动代理到 8899）
cd frontend && npm install && npm run dev

# 浏览器打开 http://localhost:5173
```

两个服务都是手动启动的进程，机器重启后需要重新拉起。服务只监听本机回环地址，
用局域网地址打不开。

顶栏徽章显示当前连的是**真实 store** 还是**隔离副本**（据 `/api/state` 的 `store_isolated`
与 `store_root`），悬浮可见 store 路径。

## 怎么用：从流程编排进，到层详情做决定

1. **研究总览**看有哪些任务、哪些事等你决定。
2. **流程编排**选任务与迭代：页面上是一串框，每个框是一类 agent 的一次工作，箭头表示上游交给
   下游的结论和证据。页首写明编排的是什么，页尾是本轮进度（本轮完成 = 每个框都已验证）。
3. 点任一框进入**层详情**：先看目标（任务原话）、这一层是什么、**这一层的 agent**（谁做、用什么
   工具包、能写哪里、不许做什么），再看它交给下游的几条结论与证据；信息交给下游之前，在「人的决定」
   里签字。动作只有三个：核对、提请决定、作废并重做；另可「开工简报」与「留档」。
4. **证据与回溯**按同一轮从上往下读：每层的结论与证据，以及它用了上游的哪几条（点一下回去）。

把某一层的工作交给 agent：在层详情点「给 agent 的简报」，复制给做这一层的 agent。agent 交付后
（写 payload 与接口卡、登记测试、`wf gate`），界面刷新即可看到新的卡片。

## 页面

| 路由 | 页面 | 数据源 | 说明 |
|---|---|---|---|
| `/` | 研究总览 | `/api/state` | 等你决定的事项（可跳转）；任务清单：目标原话、流程、各轮进展、任务级决定回执 |
| `/flow` | 流程编排 | `/api/state` `/api/guide` `/api/templates` | 「每一层由谁做、用什么」一表（agent / skills / tools / 完成标准）；所选迭代的模板节点（框），状态词 + 本层要回答的问题 + 第一条结论；开下一轮 / 结束或终止本轮 / 封板 |
| `/layer/<包>` | 层详情（不进侧栏） | `/api/package/<包>` `/api/state` `/api/guide` | 目标 · 交付 · 证据 · 人的决定 四栏，这一层的 agent（可展开完整定义），核对回执五行，开工简报 / 另读 / 上次执行，原始记录默认折叠 |
| `/layer/new?iteration=…&layer=…` | 还没有层包的框 | 同上 | 先看这一层的说明，点一下生成本层的层包 |
| `/evidence` | 证据与回溯 | `/api/state` `/api/guide` | 按迭代、按流程顺序的线性阅读；没有图 |
| `/evolution` | 演进中心 | `/api/evo-state` | Champion/Challenger 指标对比、谱系（本轮未改） |

旧地址 `/layers`、`/decisions` 自动跳转到 `/flow`、`/`。

## 只呈现没归档的任务

任务记录上的 `archived` 是一个呈现开关。归档的任务与它的层包不进 `/api/state`，所以研究总览、流程编排、证据页、
任务选择器里都不会出现；它们还在 store 里，`wf task-show` / `wf card` / `wf task-archive --restore` 仍可查可恢复。
当前只保留 cvfpu 这个示例任务，其余两个已归档。

## 层 agent 与开工简报

流程页的「每一层由谁做、用什么」直接来自 agent 定义（`platform/agents/<层>/agent.md`）。层详情左栏列出
这一层的 agent：skills 与 tools 悬停显示一句用途，可写范围与「不许做的事」原文列出，能展开完整定义正文。

页头三项说明这一层开工时的上下文：**开工简报**（时间与署名，没有则写「还没有留档」）、**另读上游几处**、
**上次执行**（agent · 模型 · 时长）。「开工简报」按钮生成给这一层 agent 的全部内容，「留档」把它写成这个包
目录下的 `brief.md` 并记下指纹——之后能查到这一层开工时拿到的是什么。

## 状态词

每个层包只有一个状态词，由核对结果机械得出，后面跟一句原因；侧栏下方「状态词是什么意思」可展开解释。

| 状态词 | 含义 |
|---|---|
| 未开始 | 这一层还没有产出 |
| 进行中 | 有产出了，还没核对通过（或已签字、还没重新核对） |
| 待人决定 | 需要你签字或做决定，做完才能交给下游 |
| 未验证 | 缺验证：没有通过的测试，或核对之后内容又改过 |
| 有问题 | 核对没通过，原因写在核对回执里 |
| 已验证 | 核对通过，下游可以用它交出的结论 |
| 已作废 | 这一层的结论作废，不再传给下游 |

`gate pass` 这类词不出现在主视图里；核对结果以五行回执呈现（交付齐全 / 证据未动 / 上游已验证 /
有人签字 / 跑过验证），每行写明核对了什么、结果是什么。原始的核对报告在「原始记录」里。

## 人的决定

- **决定回执**：谁 · 何时 · 决定了什么（一句话结论，≤80 字）。批准 / 驳回记录写成「某人 批准「…」」。
- **记一个署名的决定**：在层详情的「人的决定」里直接记，署名必填。
- **提请决定**：写一句话结论，写成待批事项，等人在同一处批准或驳回（驳回必须写理由）。
- **回执会过期**：每条回执记下当时接口卡的内容指纹。内容在其后改过，回执标为「内容在其后改过，
  需要重签」，点「重签」重新签一次。
- 任务级的回执（章程、开某一轮、结束某一轮、封板）在研究总览的任务卡和流程编排页上，同样可以
  页内批准 / 驳回。

## 新建任务

表单只有五项：标题、目标（写原话，之后每一层看到的都是这同一句）、benchmark、流程模板、章程署名
（选填）。没有任务类型，也没有成功判据——任务长什么样、怎样算完成只由流程模板决定。

- **benchmark**：从全局清单里选；没有就点「导入 benchmark」——填名字、种类和本机路径（每行一个，
  可以是负载文件，也可以是题集目录；须在仓库目录内）。
- **流程模板**：七个模板，默认完整八层。「仅 benchmark」模板不走层。
- **章程署名**：填了视为章程已批，任务直接进行中；不填则先记为待人决定，在流程编排页批准后才开始。

## 写操作的界面纪律

- **记名**：顶栏「操作人」（存在浏览器本地，各页共用）。写操作都要先填；批准、记决定、封板以它署名。
  「给 agent 的简报」不落库，不填也能用。
- **幂等**：`api.action()` 自动按「动作 + 目标 + 当前 store 版本」生成 `idempotency_key`；
  重复点击不会落第二条记录。
- **乐观并发**：每个写请求携带 `target_version`（store 哈希），store 变过则被拒
  （`store_version_conflict`）：页面状态随即自动刷新，表单不收起、已填内容保留，核对后再点一次。
- **失败不丢输入**：提交失败（含网络错误）时表单保持打开，原因显示在表单附近；只有成功才收起表单。
- **作废先预览**：「作废并重做」会让本包及全部下游作废且界面无撤销，必须先看影响范围，再过确认框。

## 后端 API

```
GET  /api/state             → 工作流状态（workflow-state schema 0.4：层包带状态词与卡片，迭代带模板节点，任务带回执）
GET  /api/package/<包>      → 层包详情：卡片 + 原始记录
GET  /api/templates         → 流程模板
GET  /api/guide             → 每层固定说明、这一层的 agent 定义（带正文）与调度 agent、标记含义
GET  /api/benchmarks        → benchmark 全局清单
GET  /api/evo-state         → 演进状态（含 lineage）
POST /api/action            → 十九种动作（application/json；跨站请求被服务端拒绝）
```

## 工程注意事项

- `tokens.css` 第一行必须是 `/* */` 注释：CSS 没有 `//` 注释，那会把下一行的 `:root`
  一起并进非法选择器，整块令牌被丢弃、界面失去全部样式。
- 各 feature 的 CSS 是全局类名，打包后合并成一个文件。跨页面共用的类（`.tf-btn` 按钮、`.give` 结论行、
  `.receipt` 回执、`.notice` 提示条、`.state-chip` 状态词）放在 `features/shared/shared.css` 与
  `features/tasks/tasks.css`；同名类不要在两个 feature 里给不同的规则。
- 类型检查：`npx tsc -b` 或 `npm run build`；`tsconfig.node.json` 已改为 `emitDeclarationOnly`，不再触发 TS6310。
- Vite 开发服务器偶尔会漏掉同一文件的第二次修改，向外提供「新代码引用了已删掉的旧函数」的
  半新半旧模块，页面渲染抛错变空白（`tsc` 仍然通过，因为磁盘上的源码是对的）。连续改完一个
  文件后在浏览器里看一眼；出现空白就重启 `npm run dev`。
- 浏览器自动化在本项目里点链接时，`locator.click()` 偶尔超时；用 `locator.evaluate((el) => el.click())`
  触发 React Router 的 click 处理即可。`window.confirm` 会卡住 `evaluate`，把点击放进 `setTimeout`
  再用 `tab.getJsDialog()` 接受或取消。
